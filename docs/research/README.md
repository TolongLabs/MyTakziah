# Research

Evidence that makes the problem, target user, impact, and feasibility credible.

## Deadline Method

With three days remaining, research must answer a submission question. Every note names the template section, canvas pillar, or judging criterion it supports. If it feeds none of them, do not spend time on it.

## Research Priorities

1. **Problem:** evidence that the selected problem exists in the chosen Malaysian context.
2. **Target User:** evidence about the primary user's situation, needs, and current journey.
3. **Feasibility:** evidence for dependencies, delivery conditions, and constraints.
4. **Impact:** credible baselines and future measures, not invented results.
5. **Innovation:** evidence about current alternatives or gaps that clarifies what is distinct.

## Evidence Standard

- Prefer official government, agency, university, organizer, or other primary sources.
- Record publisher, title, publication date when available, URL or local path, and date accessed.
- Distinguish direct evidence from team interpretation.
- Label estimates and assumptions.
- Never convert an AI-generated summary into a source.
- Never invent interview responses or imply that desk research is user validation.
- Use `[NEEDS SOURCE]` when evidence cannot be verified.

## Primary Sources

The received competition record is in `../source/`. It is an immutable record and must not be edited, moved, renamed, reformatted, or deleted. Cite a source path where relevant, but keep working notes in this directory.

## What Goes Here

| File Type           | Purpose                                                                  |
| ------------------- | ------------------------------------------------------------------------ |
| topic research note | answer one submission or rubric question with cited findings             |
| source log          | preserve citation details and access dates                               |
| user insight note   | separate actual participant input from interpretation and open questions |
| concept scorecard   | compare ideas without pretending unknowns are facts                      |

Use kebab-case names such as `target-user-friction.md` or `service-journey-evidence.md`.

## Minimum Source Record

| Field         | Required Entry                                |
| ------------- | --------------------------------------------- |
| Publisher     | organization or author                        |
| Title         | page, report, transcript, or dataset title    |
| Published     | date if available, otherwise `Not Stated`     |
| Location      | URL or local path                             |
| Accessed      | YYYY-MM-DD                                    |
| Supports      | exact claim, section, or canvas pillar        |
| Evidence Type | primary, secondary, team input, or assumption |

## Claim Gate

A claim is ready for the submission only when:

- [ ] its wording matches what the source supports;
- [ ] its source record is complete;
- [ ] any number has the correct unit and context;
- [ ] an assumption is labeled;
- [ ] the claim improves a scored section or required artifact.

## Templates

- `templates/research-note-template.md` for desk research.
- `templates/user-insight-template.md` for real team or participant input.
- `templates/concept-scorecard-template.md` for comparing track angles or concepts.

Templates are optional starting points. Citation and honesty rules are mandatory.
